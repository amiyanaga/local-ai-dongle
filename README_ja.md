# ローカルAI推論ドングル構想

> *「AIの恩恵を、クラウドに繋がらなくても、誰もが受けられるように」*

---

## この文書について

これは製品仕様書でも、ビジネスプランでもありません。

一人の人間が、AI技術の未来について考え抜いた末に辿り着いた構想を、開発者コミュニティへ向けて記したものです。書いた本人には、製品を作る技術も、企業に働きかける力も、資金も組織もありません。できることは、この構想を言葉にして、ここに置いておくことだけです。

それでも書いたのは、この構想が誰かの手で実現されれば、世界中のAI利用格差が少し縮まるかもしれないと、本気で信じているからです。

どうか、世界中のAI利用がなるべく格差少なく拡がることを、願っています。

---

## 問題意識

### クラウドAIは、今のままでは「全員のもの」にならない

現在のAI利用の大半はクラウドに依存しています。これは構造的にいくつかの問題を内包しています。

**コストの問題**　GitHub Copilotをはじめとする主要AIツールが従量課金へ移行しつつあります。個人開発者、学生、中小企業、教育機関にとって、AIは「使えるもの」から「コストを計算しながら使うもの」になりつつある。

**インフラの問題**　クラウドAIはデータセンターへの巨大な投資と、膨大な電力消費を前提としています。需要が増えるほど、その負荷は集中します。

**格差の問題**　安定したインターネット接続と、継続的な課金能力を持つ人だけが、AIの恩恵を受けられる構造は、技術の民主化とは逆方向です。

**プライバシーの問題**　センシティブなコードや文書をクラウドに送ることへの懸念は、開発者コミュニティで広く共有されています。

## 構想の核心

### eGPUの発想を、ローカルAI推論に転用する

発想の出発点はシンプルです。

eGPU（外付けGPUボックス）という概念はすでに存在します。既存のPCに外付けで演算能力を追加する、という枠組みは技術的に確立されています。

**この枠組みを、AI推論専用に特化して転用する。**

映像出力のためのGPU負荷と違い、テキストベースのAI推論が必要とするI/O帯域は桁違いに小さい。USB 3.1 / 3.2（5〜20Gbps）で十分に成立します。モデルウェイトをデバイス内に常駐させ、推論をデバイス内で完結させれば、ホストPCとのやり取りはテキストのみになります。

つまり——

- 新しいPCを買わなくていい
- 高速な外部接続規格を必要としない
- 既存のUSBポートで動く
- 消費電力は数ワット程度に収まる

**世界中の既存PCが、そのままAI PCになれる。**

## 技術的な考え方

### なぜUSB 3.1/3.2で足りるのか

| 用途 | 必要帯域の目安 |
|---|---|
| 4K映像出力（eGPU） | 〜12Gbps |
| テキストAI推論のI/O | 数十Kbps〜数Mbps |

推論の計算はデバイス内で完結します。ホストPCに返すのはテキストトークンのみ。帯域のボトルネックは原理的に発生しません。

### 対応モデルの考え方

軽量〜中量級の量子化モデルがターゲットです。

- Llama 3 8B（Q4量子化）：約4GB
- Mistral 7B（Q4量子化）：約4GB
- その他の7〜13Bクラスの量子化モデル

これらはローカルで動作可能なサイズであり、コーディング補助、文書要約、Q&A、翻訳など、開発者が日常的に必要とするタスクの大半をカバーします。

### 電力について

USB給電の範囲（最大100W、実用5〜20W）で推論専用チップを駆動することは、現在の推論特化チップの消費電力特性から見て、技術的に成立します。

## なぜ今なのか

### 開発者コミュニティが動く条件が揃っている

**GitHub Copilot の従量課金移行**　最も身近なAI開発ツールがコスト計算の対象になった。「ローカルで動くならその方がいい」という動機が、開発者の間でかつてなく強くなっています。

**オープンモデルの成熟**　Llama、Mistral、Qwen をはじめとするオープンウェイトモデルが、実用レベルに達しました。ローカル推論の「中身」が揃っています。

**llama.cpp などの推論エンジン**　CPU・NPU向けの効率的な推論エンジンがオープンソースで存在します。ソフトウェアスタックの基盤はすでにあります。

**ハードウェアの民主化**　推論特化チップ（NPU）の設計・製造コストは下がり続けています。専用ドングルを現実的なコストで作れる時代になっています。

## 最大の課題：ドライバーの標準化

構想の中で最も難しいのは、技術でも製造でもなく、**ドライバーの標準化**です。

OSがこのデバイスを「推論アクセラレータ」として認識し、アプリケーションから透過的に使えるようになるためには、標準的なインターフェースが必要です。

歴史が示すのは、**標準化は普及の後からついてくる**ということです。

USB規格がそうでした。Wi-Fiがそうでした。開発者コミュニティが自発的にドライバーを書き、GitHubに上げ、使う人が増え、OSベンダーが無視できなくなる。その順番でしか、本当の標準化は起きません。

**だからこそ、最初に動くのは開発者でなければならない。**

## 誰が作るべきか

この構想は、特定の企業を主役に想定していません。

大企業には「自社の既存ビジネスを壊す」というジレンマがあります。クラウド収益を持つ企業が、ローカル化を積極的に推進することには構造的な矛盾があります。

**最も適しているのは、そのジレンマを持たないプレイヤーです。**

- 推論特化の新興チップメーカー（Groq、Tenstorrent、Etchedなど）
- NPU設計に強いファブレス企業（Qualcomm、MediaTekなど）
- オープンソースコミュニティ発のハードウェアプロジェクト

重要なのは製造者よりも、**エコシステムの条件**です。

- オープンなドライバー仕様
- 標準的な推論API
- 複数ベンダーが参入できる非独占的な設計

## この構想が実現したとき

### 誰が得をするのか

**開発者**　GitHub Copilotの従量課金から解放される。プライベートなコードをクラウドに送らなくていい。オフライン環境でも推論できる。

**教育機関**　定額のハードウェアコストで、生徒全員にAIアクセスを提供できる。クラウド従量課金のリスクなしに、AI教育を実装できる。

**中小企業**　AIコストが予測可能になる。センシティブなデータをクラウドに出さずに済む。

**クラウドプロバイダー**　軽量推論がローカルへ移行することで、データセンターのGPUリソースが大規模モデルの推論に集中できる。インフラの効率が上がる。

**地球環境**　推論をエッジに分散させることで、データセンターの集中的な電力消費を緩和できる。

### 誰のためのAIか

AIは今、インターネット接続と課金能力を持つ人のものです。

この構想が実現すれば、それが少し変わります。安定したクラウド接続がなくても、継続的な課金ができなくても、手元にデバイスさえあれば推論できる。

格差の完全な解消ではありません。でも、縮めることはできます。
